# Confidentiality Review

This review defines the publication boundary for the Apple Developer Academy portfolio. It applies to the three internship case studies and all RIS evidence used to draft them.

## Public-safe material

- Generic project purpose and intended workflow
- The applicant's high-level responsibilities
- Problem-solving approach, trade-offs, testing categories, and lessons
- Broad technology categories such as Python, REST APIs, asynchronous processing, vision-assisted analysis, and automated tests
- Reconstructed diagrams containing dummy labels only
- Honest project status without production, revenue, accuracy, or scale claims

## Excluded from every public artifact

- Company, client, customer, partner, and employee identities
- Real auction listings, certificates, URLs, prices, parties, and outcomes
- Real legal names, case numbers, documents, decisions, courts, and result payloads
- Uploaded customer documents and any identity-document image
- Source code, repository paths, internal endpoints, credentials, tokens, and environment values
- Production database, collection, table, queue, storage, deployment, and network structure
- Internal business rules, provider-specific decision logic, and countermeasure details
- Prompts, proprietary model configuration, model-routing rules, and vendor diagnostics
- Exact private test counts, throughput, usage, financial, accuracy, and operational metrics
- Internal roadmaps, staffing, infrastructure capacity, and supervisor discussions

## Project-specific decisions

### Digital Auction Platform

Publish the independent request lifecycle, fault isolation, status clarity, conservative source validation, and learning. Exclude every real record and source-specific retrieval rule. The intentionally excluded scraper project is not analyzed or presented.

### Document Authenticity Detection System

Publish the reviewer-assistance framing, strict intake, private workflow, structured findings, cleanup, validation, and uncertainty language. Exclude all real documents, prompts, vendor/model configuration, storage locations, endpoints, retention settings, and production claims.

### Legal Record Verification Workflow

Publish the multi-source orchestration, provenance, conservative identity confidence, graceful partial failure, and privacy reasoning. Exclude source-specific access details, client context, personal records, legal documents, internal decision rules, and case-level examples.

## Required publication label

> Confidential Internship Project — details and visuals have been anonymized or reconstructed to protect proprietary information.

The publication field for all three internship projects is:

> Not public — confidential internship project

## Security finding outside the internship work

The public Stuggy repository contains hard-coded connection values. Their values were not copied into this portfolio or this review. The source link is withheld in the local portfolio build until those values are removed from the repository and rotated where necessary.
